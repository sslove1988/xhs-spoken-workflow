# 脚本生成

## 使用前提

先遵守 `../00-shared-principles/SKILL.md`，并优先读取 `../USER-PROFILE.md`。如果本模块被单独调用且账号配置不完整，提醒一次；如果由 `../10-master-workflow/SKILL.md` 路由且入口已经提醒，不要重复提醒。如果执行失败，先检查 `../99-error-memory/known-solutions.md`，再尝试新的修复。

这个 skill 只负责从“已确定或基本确定的选题”生成草稿，不替用户决定是否发布。

如果输入包含对标账号、爆款笔记、高赞评论或热点内容，只能参考：

- 选题角度
- 用户需求
- 评论反馈
- 内容节奏
- 标题 / hook 逻辑
- 封面逻辑

禁止照搬标题、正文、观点、脚本、个人经历或具体表达。禁止洗稿。

## 账号配置规则

脚本必须服务于 `../USER-PROFILE.md` 中的账号定位、目标用户、表达风格、内容边界和平台形式。

不要默认账号定位、平台或语气。只有使用者在配置或本轮输入中填写的身份、经验、设备、场景、表达风格和输出形式，才可以写进脚本。

## 可接受输入

用户可能提供：

- 选题
- 平台：小红书 / B站 / 抖音 / 视频号
- 想做图文、口播或视频
- 参考账号、爆款笔记或评论洞察
- 想表达的观点
- 自己的真实经历、拍摄条件、设备、素材
- `USER-PROFILE.md` 中的账号配置

信息不足时，先给轻量草稿，并列出需要用户补充的真实信息。

## 默认输出策略

真实发布内容默认先给“可发布重点版”，不要把一个选题展开成完整报告。除非用户明确要求完整版本，否则少给解释，多给能直接改的标题、口播、画面和图文结构。

当用户没有指定形式，但选题适合视频表达时，优先按视频内容处理，再补充小红书图文结构。跨小红书 / B站 / 视频号共用时，优先给 2-3 分钟完整口播脚本；30-45 秒短视频脚本作为补充版本，不要只给短版。

## 生成流程

1. 判断选题是否已经通过 `../02-topic-scoring/SKILL.md`，没有的话先做简短适配判断。
2. 明确脚本目标：短视频、2-3 分钟视频、图文，或混合发布。
3. 提取用户自己的真实场景，不编造经历。
4. 设计 hook：优先真实场景、痛点、反差、误解澄清、体验结果。
5. 先写可发布版本，不默认同时输出原始稿和改写稿。
6. 用活人感改写思路自检：删除 AI 味、官方腔、营销腔和硬教程腔。
7. 输出视频画面结构、图文结构和人工修改节点。

## Hook 类型

优先使用适合中文小红书和短视频的 hook：

- 场景型：我最近在整理自己的工作流时发现...
- 痛点型：我以前最烦的是...
- 误解澄清型：这个功能不是为了炫技，它真正有用的是...
- 体验结果型：我试了一段时间，最明显的变化是...
- 对比型：以前我会这样做，现在我改成...
- 配置人群视角：如果你也遇到类似问题...

避免：

- 一键爆款
- 轻松涨粉
- 彻底改变人生
- 必看 / 震惊 / 不看后悔
- 过强专家口吻

## 输出格式

### 当前脚本类型

图文版 / 口播版 / 视频分镜版 / 混合版。

### 参考来源与原创性声明

说明参考了哪些方向，只参考了什么，并明确没有照搬什么。

### 标题方向

给 3-5 个标题，真实、具体、有点击欲但不标题党。标题可以直接一点，但不能夸张承诺。

### 30-45 秒短视频脚本

适合短视频时输出一版轻量脚本。不要塞满所有信息，只保留一个核心钩子、一个真实场景和一个边界。

### 2-3 分钟完整视频脚本

跨小红书 / B站 / 视频号共用，或用户需要完整表达时优先输出。要求：

- 真实，并符合配置中的表达风格
- 先讲为什么做，再讲能做什么
- 保留困惑、犹豫、尝试感
- 不官方、不营销、不硬技术
- 不夸张承诺
- 不把所有信息都塞满，给口播留停顿和转折

### 可发布正文

给一版轻量小红书正文或视频简介。正文要像真实创作者分享，不要像项目说明书。

### 开头 5 秒

给 2-3 个可选开头，优先真实背景、误解澄清或配置中的目标用户视角。

### 视频画面结构

优先给不露脸也能拍的低成本画面安排，例如桌面实拍、屏幕录制、设备联动、素材前后对比、工具界面局部。

### 小红书图文结构

如适合图文发布，给 6-8 页结构。每页只保留一个重点，不写成教程长文。

### 原始草稿说明

如果需要展示修改过程，可以补充原始草稿或改写说明；默认不要输出两套长稿。

### 结尾引导

使用轻量互动，不要强转化，不要像卖课或工具广告。

### 需要我人工修改的地方

至少提醒：

- 哪些地方需要我补充真实经历
- 哪些说法不像我
- 哪些观点需要我自己确认
- 是否有照搬风险
- 是否太营销号、太硬技术或太像教程
- 是否适合我现在的拍摄条件
- 是否符合我的账号配置和内容边界
- AI 只负责整理、分析和生成初稿，最终判断必须由真人完成

## 自检清单

输出前检查：

- 是否保留“AI 只负责整理、分析和生成初稿，最终判断必须由真人完成”
- 是否没有照搬对标内容
- 是否有真实使用场景
- 是否有明确开头
- 是否有信息增量或情绪价值
- 是否适合配置中的主要平台
- 是否适合沉淀到 `../../data/script-drafts.md`
